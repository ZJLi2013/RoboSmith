# RoboSmith 设计

> 草案：取代旧的 `design.md`（数据生成时代的 teacher / student 叙述）。

## 目标

在真实场景的仿真孪生里评测 agentic 机器人与 VLA。三块：**场景**（真实视频变成可交互孪生）、**操作**（自带的基本 agentic 操作证明任务可解）、**评测**（被测方跑任务，判定并归因失败）。

## 问题

代码是从数据生成流水线演化来的，目标是「让演示成功」，所以每一层都在**放过不成立的东西**：放不下的物体被跳过、规划不出的动作被硬推、失败照样判成功。
上游放过的问题到下游变成别的症状，原因因此分不清。缺的不是某个组件，而是每层都没有「不成立就失败」的契约。

## 设计原则

- **一套几何**：放置、检查、规划、判定都用仿真里的同一份几何。
- **不成立就失败**：每层带原因失败，不跳过、不降级。

## 三部分

- [场景](scene.md)：一个场景成立 = 几何一致、物体静止、可动物体能被抓起；每次实例化都自动检查，不过即无效。
- [操作](manipulation.md)：一个动作能执行 = 执行前已在仿真几何里验证可行；所有动作经同一道门。
- [评测](evaluation.md)：被测方经不绑框架的接口接入；报告给出 never / lost 归因。

当前代码怎么走：[调用链](call-chain.md)。

## 顺序

1. 场景检查（其余两块都依赖它）
2. 操作的执行门，先在两个现有场景上做到可证明
3. 评测接口与报告
4. 真实视频导入

数据生成时代留下的部分（图像转 3D、训练脚本、开环验证）随重构删除。
