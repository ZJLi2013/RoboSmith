# 场景：真实场景变成可交互的孪生

总体设计见 [system-design](system-design.md)。

## 要保证什么

一个场景成立 = **几何一致、物体静止、可动物体能被抓起**。真实视频导入的场景过了这三条才算孪生；agent 写的场景同样。

## 现在有什么

- **资产**：agent 写 Blender 程序生成单个物体（含铰接件）；独立 LLM 评审自己写仿真探针取证后准入；准入资产按内容 hash 发布到 Hugging Face，新 clone 可完整复现；查重分两层（hash 拦精确重复，近似候选交 LLM 判）。
- **场景**：agent 写 YAML（物体、关系、对执行方隐藏的成功树、seed），求解器按 seed 摆放，加载进 Genesis，沉降后检查是否静止。
- **真实场景导入**：视频经外部重建（AHa-3D）→ agent 建房间 → 按快照导入，物体各自编成资产。只在 BEHAVIOR 仿真视频上跑过（几何残差中位数 6.2 cm），真实视频没跑过。

## 问题

三条都没有被强制：

- **几何不一致**：同一个物体在生成、摆放、评审探针、判定里用的是不同的几何近似（盒子、网格、包围盒）。
- **静止只在部分时机检查**，建场景时不查；放不下的物体被跳过，场景照样加载。
- **没有人检查可动物体能不能抓起**；可抓只在运行任务时才暴露（例：骰子被摆在立柱旁，俯视抓取压进立柱）。
- 桌子在场景文件里是一个资产名，仿真里其实是程序生成的盒子。
- 导入的场景过不了静止检查：导入时能静止，后来物体被顶开约 0.1 m，中间有回归、原因未查。

## 设计

- 一套几何：资产只用一种碰撞表示，摆放、检查、判定都读仿真里的同一份。
- **世界检查**：场景每次实例化都自动做——几何一致、静止、每个可动物体经操作层的执行门能抓起；不过即场景无效，结果反馈给写场景的 agent 返工。
- 摆放 fail-closed：任一物体放不下，场景无效。
- 真实视频导入的产物必须过世界检查才算孪生。

## 已定 / 不做

- 资产只走 agentic 生成（agent 写程序或操作工具）；不用图像 / 文本转 3D 模型、不用前馈场景模型（网格不透明，无零件与关节）。
- 资产即物理尺寸，不在场景里缩放。
- 场景求解器只管摆放与可静止，不判任务可解（任务可解由操作层证明）。

## 下一步
